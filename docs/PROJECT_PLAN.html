1. Project Direction

The team will build an educational machine-learning system that classifies a person's obesity-risk category using demographic, physical, nutritional, and lifestyle information. The task is a seven-class classification problem with NObeyesdad as the target variable.

Important approval gate: The dataset must be validated by the instructor before EDA, preprocessing, model training, or application development. Until approval is recorded, the repository contains planning and structure only.

Users and stakeholders

  • Students and academic evaluators
  • Researchers and data-mining learners
  • Demonstration users and non-technical stakeholders

System outcome

  • Validated user inputs
  • Predicted obesity-risk category
  • Clear confidence/probability information
  • Educational explanation and limitations

4. Full Project Workflow

STAGE 1

Problem understanding

Define the real-world scenario, prediction objective, target variable, users, stakeholders, decisions, inputs, outputs, and educational/non-clinical scope.

STAGE 2

Dataset identification and validation

Prepare the proposal with source, citation, context, dimensions, feature groups, task, suitability, data-quality observations, limitations, ethics, privacy, licensing, and accessibility. Obtain approval before development.

STAGE 3

Data understanding and EDA

Inspect structure, meanings, types, distributions, relationships, missing values, duplicates, identifiers, invalid values, outliers, unusual observations, class balance, visualisations, and leakage risks.

STAGE 4

Preprocessing and feature engineering

Handle missing, duplicate, invalid, and justified outlier cases; encode categorical variables; scale where required; decide identifier handling; select or engineer features; split data without leakage.

STAGE 5

Progress Evaluation 1

Individual viva on the problem, dataset, EDA, quality issues, preprocessing, feature engineering, leakage prevention, and personal contribution.

STAGE 6

Model development

Implement and compare at least four suitable algorithms using an appropriate validation strategy and classification metrics. Record experiments and explain why results differ.

STAGE 7

Model optimization and selection

Tune suitable models, investigate feature/model improvements, compare tuned and baseline results, and justify the final model.

STAGE 8

Progress Evaluation 2

Individual viva on algorithms, validation, metrics, tuning, optimization, interpretation, final model selection, and personal contribution.

STAGE 9

Backend development

Load the final model and preprocessing pipeline, validate inputs, generate predictions, return meaningful results, and handle invalid or missing inputs.

STAGE 10

Frontend and user experience

Provide clear input controls, validation, prediction results, understandable explanations, and a working frontend-backend end-to-end flow.

STAGE 11

Technical report

Cover problem, requirements, dataset, EDA, preprocessing, features, algorithms, evaluation, tuning, final model, architecture, implementation, testing, limitations, future work, and contributions.

STAGE 12

Final presentation and demonstration

Explain the business problem and evidence-based solution to non-technical stakeholders, demonstrate the system, communicate recommendations, and answer questions individually.
